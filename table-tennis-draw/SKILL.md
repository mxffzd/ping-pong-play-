# 乒乓球分组

把用户本次提供的名单、组数、种子规则变成可核查的分组、组内循环赛和淘汰赛对战图。使用中文，说明保持简洁。

## 1. 获取本次输入

- 接受聊天名单、CSV、Excel、图片或已有报名表。处理文件时使用环境中适用的表格或文档技能；图片识别不清的姓名先列出核对。
- 将本次任务的“分组个数”“种子个数”“种子人选”作为三个明确输入，并接受与名单一同写在聊天中的自然语言，不要求另填配置文件。另明确参赛项目和种子保护方式；已经提供的内容不重复询问。
- 分组个数须为1至有效参赛人数之间的整数。种子个数为非负整数；种子人选可用姓名或参赛编号指定。同名人选必须结合编号或班级确认，不自动挑选其中一人。
- 核对种子人选均在本次有效名单中，且是互不重复的参赛单位；实际人选数必须等于种子个数。不一致时列出差异并补齐，不能自动凑数、删人或选择最先报名者。
- 种子个数为0时，人选应为空，按无种子保护分组。只提供了明确人选而未写种子个数时，可据此计算并说明人数；只提供种子个数而无人选时，必须补齐人选。未提及种子时保留下面的无种子默认规则。
- “各种子分别在不同小组”的规则下，种子个数不能超过分组个数；冲突时提示调整。其他保护方式按用户明确规则处理，不擅自改成不同组。
- 种子规则要区分：哪些选手受保护，以及如何保护。例如“前8号种子各在不同小组”；仅给出种子名单但未说明保护方式时，只补问这一项。
- 未提供种子名单且未要求种子保护时，按无种子随机分组处理并说明。默认各组人数差不超过1、组号从1开始、组内顺序随机；这些默认项无需额外确认。
- 男女、单打、双打等分别分组，除非用户指定混合。双打每对搭档是一个参赛单位，不拆开抽签。
- 固定分组、同班回避、指定每组人数等属于额外约束，先厘清硬性要求或尽量满足。不得悄悄忽略，也不得把“尽量”写成“保证”。
- 不沿用历史比赛的人数、名单、组数、种子名单或淘汰赛规则。
- 本技能默认接着生成“每组前2名出线”的单败淘汰赛预设图。用户只要分组或循环表时跳过淘汰赛；已经给出的出线规则优先。淘汰赛需明确种子强弱顺序，不能把先前仅作保护标记的列举顺序当成实力排名。

## 2. 整理并核对名单

- 保留原始资料；为每个参赛单位分配稳定且唯一的编号。去掉首尾空白，保留姓名原字形。
- 同名不等于同一人。结合学号/报名编号/班级识别重复报名；只有证据足够或用户确认后才去重。错别字、疑似异体字不得擅自合并。
- 报告原始记录数、有效参赛单位数、去重/补录/改名情况及待确认项。缺少关键身份信息时先核对，不把可疑记录静默删除。
- 抽签前用一句话说明有效人数、组数、各组人数分布及实际保护的种子数。当前指令已经授权抽签时直接执行；不额外设置确认关卡。

可接受的调用示例：

```text
使用 $table-tennis-draw 处理这份名单。
分组个数：8
种子个数：4
种子人选：张三、李四、王五、赵六
种子强弱顺序：张三、李四、王五、赵六（由强到弱）
保护方式：这4名种子分别在不同小组。
淘汰赛：每组前2名出线，先生成第二名待抽签的预设图。
```

## 3. 执行分组

普通均衡分组、指定组别和“前K号种子不同组”使用 [scripts/draw.py](scripts/draw.py)。它只依赖 Python 标准库。输入字段及命令见 [references/input-format.md](references/input-format.md)。

- 保存清理后的规范名单，使用编号判断是否遗漏和重复，不用姓名作唯一键。
- 用 `--protect-top-k K` 明确受保护的种子名次上限；其他种子按普通参赛单位抽签。`K=0` 表示不保护。
- 用户直接指定S名受保护种子、要求分别不同组时，将已核对的参赛编号写入规范名单，在本次规范副本中按用户给出的排序（无排序则仅按列举顺序编码）赋 `seed_rank=1…S`，调用 `--groups G --protect-top-k S`。这只是保护标记，不推断选手实力；原始名单保留。若还需保留额外种子名次或部分保护，依用户规则映射并核对，不让非选中者误入受保护范围。
- 记录用于重现抽签的随机数参数、算法版本、规范名单 SHA-256 和规则。随机数参数与“种子选手”是两个不同概念。
- 保持组内顺序随机。公开分组表默认不标种子，编号用于区分同名参赛者；种子信息保存在组织者核验记录中。
- 结果生成后不得因“不满意”而暗中重抽。用户明确要求重抽或修改规则时保留旧结果，另存新版本并说明原因。
- 规则冲突或无法满足时指出具体冲突。分组脚本不支持同班回避或指定不均衡人数，有这些要求时另行实现并验证；淘汰赛分区使用下面的专用步骤。

## 4. 验证并交付

独立核对源名单与结果：编号集合相同、人数相同、每人仅出现一次、各组人数符合规则、受保护种子分散、固定组别无误。

- 默认交付可编辑的 Excel 分组及循环对战表，包含“分组总览”“各组名单”“核验记录”和下述循环赛工作表。根据环境加载适用的表格技能，保留脚本生成的 JSON 作为抽签依据。表格导出须逐项对应 JSON，不重新随机。用户明确只要分组时跳过循环表。
- 如果当前环境不能生成 Excel，明确交付 UTF-8 CSV 和核验 JSON，不把 CSV 称为 Excel 工作簿。
- 核验记录属于组织者材料，含随机数参数、规则、名单哈希及检查结果；公开分享时仅导出不含种子标记的分组名单。
- 在已有核验记录中列明本次分组个数、种子个数、最终种子人选及对应编号，供用户核对；不为这三个输入另建配置页或应用。
- 可设置字体的主标题和各级小标题使用黑色微软雅黑加粗，明确设置中文与西文字体，并清除主题字体覆盖；当前模板或用户另有要求时服从它。
- 分组后默认生成组内单循环对战表。若只是给已有结果加表，读取原来的 `抽签核验.json`，不重新抽签、不改组内顺序。
- 用 [scripts/round_robin.py](scripts/round_robin.py) 将分组结果转换为分轮对阵，检查每组完整覆盖所有无序对、每轮每人至多出场一次。奇数人数每轮轮空一人，轮空不记成比赛；一人组无比赛。
- 按 [references/round-robin.md](references/round-robin.md) 创建“循环赛对阵”和“组内循环表”。可导入 [scripts/round_robin_tables.mjs](scripts/round_robin_tables.mjs) 中的 `addRoundRobinTables(workbook, schedule)` 直接添加这两张表；它使用表格技能的公开 Workbook API。
- N×N矩阵的行、列均显示对应选手姓名，列标题不使用“1号、2号”等代称；同组有重名时在列标题附参赛编号区分。
- 每组每对参赛单位交手一次，场次数为 n(n−1)/2。不把分轮清单称为已排好场地和时间的赛程。没有轮次要求时也保留默认分轮，方便使用。
- 未给成绩时比分留空，不填造胜负或排名。比分只在“循环赛对阵”的黄色格录入一次，N×N矩阵从同一数据源读取，按行选手在前显示，反向格交换局数；未完整录入或比分无效时矩阵保持空白。0局是有效输入，不当成空白。
- 不假定几局几胜或同分排名规则；这些规则未给出时仅提供双方赢得局数的录入及展示。胜负统计、积分排名、场地时间编排和打印 PDF 按用户需要另加。
- 文件保存到本次工作区的 `outputs` 或用户指定目录，最终简述组数、人数分布、种子保护、核验结果并提供文件链接。

## 5. 淘汰赛编排与对战图

分组与循环赛后，按 [references/knockout.md](references/knockout.md) 运行淘汰赛流程；若只给现有分组增加淘汰图，直接复用原 `抽签核验.json`，不重新分组。

- 默认每组前2名出线，先确定各组第一的签位；种子取得组第一时，按明确强弱顺序分级保护。预设签位跟组第一绑定，种子只获第二时不再保证原种子保护。
- 先生成预设签位图，第二名保留待抽签。赛后有完整、明确的第一/第二名次且用户要求抽签时，再把第二名抽入同组第一所在半区的相反半区；不逐轮重抽。
- 没有小组成绩或名次时使用“第X组第一／第二”等占位，不推断种子必然出线。赛后人选用编号匹配原名单，保留同名区分。
- 用 `scripts/knockout.py` 生成签位、第二名抽签池和核验 JSON，用 `scripts/render_knockout.py` 生成 PDF 与 PNG。读取并遵守适用的 PDF 技能，渲染后检查连线、文字和页边界。
- 公开对战图不显示种子身份、种子编号或种子保护说明；内部仍保存分区依据。只显示小组名次／实际出线者、比赛胜者占位、第二名抽签安排和晋级连线。
- 当前自动模式支持1、2、4、8、16、32组，每组前2名。其他组数、出线人数或轮空制度先明确规则并另行编排，不默默改变人数或淘汰赛制。
