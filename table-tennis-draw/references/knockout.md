# 淘汰赛编排

本技能当前采用每组前2名出线、单败淘汰。支持1、2、4、8、16、32组，对应2至64人签表。其他组数或出线方案不自动套用轮空。

## 输入和保护

复用分组结果 `抽签核验.json`，只使用其 `protect_top_k` 范围内的选手作为保护种子。需确认这些选手有明确强弱顺序，再传 `--ranked-seeds`；未排序的保护名单不得擅自推定强弱。若仅缺强弱排序，可继续交付已完成的分组和循环表，再补齐淘汰赛所需顺序。

预设签位跟组第一绑定，不跟种子本人无条件绑定。种子拿到组第一时，前2号分处两半区、前4号分处四区、前8号分处八区，以此类推。当前8组8种子的固定模板中，沿签表从上到下的组第一来源依次对应种子 `1、8、5、4、3、6、7、2`，与已确定的方案一致。

未保护的小组第一占据其余组第一签位，随机分配并保存重现参数。每组第二只能进入与本组第一相反的半区，首轮始终是第一对第二。同组两人最早在决赛相遇。

## 小组赛前：预设图

```text
python <skill目录>/scripts/knockout.py --input <抽签核验.json> --ranked-seeds --output <新的淘汰赛目录>
```

无受保护种子时不需要 `--ranked-seeds`。输出 `淘汰赛编排.json`（组织者内部记录）及不含种子标记的 `淘汰赛签位.csv`。默认第二名未抽签，图中标“待抽签”，并列出上下半区的可抽组别和签位。

## 小组赛后：登记并抽签

先把用户明确提供的完整名次整理成 UTF-8 CSV，列为 `group,rank,id`，每组恰好两行，rank分别为1、2。编号必须来自原组，同一人不能占两席。不要仅凭种子身份、未完成比分或未确定的同分规则填写名次。

```text
python <skill目录>/scripts/knockout.py --input <抽签核验.json> --ranked-seeds \
  --qualifiers <明确的小组名次.csv> --draw-runners-up \
  --preset <已公布的淘汰赛编排.json> --output <新的赛后淘汰赛目录>
```

提供 `--preset` 会锁定已公布的组第一签位，避免因赛后重新运行而改变签表。没有旧预设图时可省略该参数；有旧预设图时应使用它。仅更新名次而未授权第二名抽签时不要加 `--draw-runners-up`。

如果旧签表已经完成第二名抽签，补录真实姓名时只用 `--preset` 和 `--qualifiers`，不再加 `--draw-runners-up`；脚本会保留第二名原签位。旧签表必须对应同一份原分组文件。

`--draw-runners-up` 没有实际名次文件时只抽组第二占位，属于用户明确要求的模拟抽签；不能宣称已确定真实选手。`--random-seed` 用于重现抽签，不是种子选手身份。

## 生成公开图

加载当前运行环境后，使用其 Python、Poppler 和可用中文字体路径：

```text
python <skill目录>/scripts/render_knockout.py --input <淘汰赛编排.json> \
  --pdftoppm <当前Poppler的pdftoppm路径>
```

Windows默认使用微软雅黑及加粗字体；其他环境可用 `--font`、`--bold-font` 指定实际存在的中文字体。输出在 JSON 同目录，为 `淘汰赛对战图.pdf` 与 `淘汰赛对战图.png`。主标题和各级标题为黑色微软雅黑加粗；公开图不显示种子信息。人数多时画布随签表增大，不压缩文字塞入固定纸张。

绘图前按 PDF 技能记录创建操作，完成后用实际 PNG 目视检查。图里是预设名次或已确认人选，不填造比分、胜者或冠军。核对所有出线席位只出现一次、首轮第一对第二、同组分属两半区，及种子分级分离效果。

输出目录和已有图文件均拒绝覆盖；另存新版本并保留旧抽签记录。
